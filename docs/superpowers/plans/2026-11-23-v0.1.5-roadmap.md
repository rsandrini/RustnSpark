# v0.1.5 Roadmap (master plan)

> **For agentic workers:** this is the ORDER and the GATES for v0.1.5, not a task-by-task script. When a slice is picked up, write its own
> plan in this folder first (REQUIRED SUB-SKILL: superpowers:writing-plans), then execute it with superpowers:subagent-driven-development
> or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ship ONE v0.1.5 at the end of everything below = a game-like UI over the whole game, then a richer mission world (more offers,
short and long jobs, new mission kinds, a bigger map, refuel between ports), plus the bugs the owner finds testing v0.1.4 in prod.
Ship-structure damage moved to v0.1.6 (`docs/TODO_v0.1.6.md`).

**Architecture:** every slice lands on `develop` and is promoted by the owner only when ALL of v0.1.5 is done (one tag, `v0.1.5`; no
`a`/`b` tags per block). A prod hotfix, if one is needed meanwhile, takes its own letter on the CURRENT release (`v0.1.4b`). The UI comes first, so the new mission kinds are built once, on the new component kit.

**Tech Stack:** NestJS + Prisma + Postgres + Redis (api, worker), React + Vite (web), Playwright (e2e), the economy sim (`apps/api/sim`).

**Spec:** `docs/TODO_v0.1.5.md` (owner's items 1 to 6), `docs/design/game-ui-v0.2-plan.md` (UI phases, mockups in
`docs/design/game-ui-v0.2/`), `design/missoes-compostas-e-reabastecimento-v0.2.md` section 2 (refuel on legs).

## Global Constraints

- Commit on `develop` (or a branch from it); NEVER on `release/*`, `main`, `master`. The owner promotes. Run `git branch --show-current` before every commit.
- Code in English; every player-facing string in en AND pt-BR, no hard-coded text; removed copy removed from both locale files.
- Admin owns every tunable number: the DB wins over TS defaults, changes take effect at once. New knobs go in the config registry.
- `apps/api/src` must not import the contract package (the Docker api build has none); new error codes need en + pt-BR.
- Missions resolve in the `worker` container: rebuild api AND worker after an engine change.
- The seed fills data only when empty: a map, part or mission-template change needs a MIGRATION for prod.
- Before any push: grep the old literals, run `test:e2e`; during work run only the specs of touched files. Sims need Node 22.
- The connection ports are shown everywhere a part appears, never abstracted. The installed parts on the ship stay as they are (+ type subtitle).

## Review Focus

- A pilot with a mission accepted or flying while a migration adds mission types or changes the map: nothing may break, nothing may be lost.
- A ship that cannot take any offer (no radar, no repair tool, no hold): the board must still show a takeable job (`starter_guarantee`) and say why the rest are blocked.
- 390px phone width on every redone screen (the plan marks it as not mocked up).
- Missing pt-BR (or a stale key) on any new label; the e2e literals that break when copy changes.
- The prologue sandbox (`apps/web/src/features/prologue/sandbox`) and the admin screens must follow every new mission kind and every UI change.

## Decisions

- Decided (owner, 2026-11-23): one `v0.1.5` tag at the end; no sound; ship damage moves to v0.1.6; bugs found testing v0.1.4 in prod join the list.
- Decided: art for the parts is the last task of the version (slice 1.9), temporary drawn art, discussed later; it never blocks the UI.
- Decided: **fight in a zone** = waves of pirates with a TARGET, scored (a score is kept and compared with the target), and a partial result
  that reaches the target still counts as a victory. The idea behind it is CONQUEST: each faction fights to control a zone, first against
  the pirates, then the faction with the most points at the end conquers the area/port/region. In v0.1.5 ONLY the fight is built: no points
  per faction, no conquest (that is v0.2, War).
- Decided: **fuel transport** = a NEW separate cargo-tank part family (not the cargo hold, not the ship's own fuel tank), with different
  tank kinds: water, chemicals, fuel (cargo fuel is NOT consumed by the ship). Content: a part family per the parts-catalog rules (tiers,
  sizes), a tank kind on the cargo, requirement `needs a tank of that kind`.
- Open: UI subtitle layout A or B (artifact shown to the owner, before slice 1.1).
