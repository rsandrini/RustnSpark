**Goal:** the game answers every action: numbers count up instead of jumping, a finished mission is a small reward moment, the phone buzzes where the browser allows (with an opt-out), and the screens carry less explaining text (help moves behind a "?" tip).

**Owner scope note (2026-11-24, 2026-11-25):** NO SOUND in this version; no browser/e2e/screenshot task; the owner reviews visually later. Unit specs and the final whole-slice review still run.

Existing pieces to reuse: `ui/feedback.tsx` (toast with amount, one raw `navigator.vibrate` call), `ui/use-wallet-answer.ts` (wallet pulse and `+/-` delta), `ui/AccountMenu.tsx` (the wallet text), `features/report/mission-result-popup.tsx` and `report.page.tsx` (credits shown as plain text), `ui/kit/ResourceChip.tsx` (count-up + flash), 39 existing `prefers-reduced-motion` uses.

**Tech Stack:** React + Vite, react-i18next, CSS animations, Vitest + Testing Library. Web only; no server change.

## Global Constraints

- Work on `develop`, one commit per task. `git branch --show-current` before every commit; never `release/*`, `main`, `master`. Pushing `develop` is allowed.
- Code in English; every player-facing string in en AND pt-BR; removed copy removed from both locale files unless another screen still uses it (grep `apps/web/src` and `apps/web/e2e`).
- `prefers-reduced-motion: reduce` turns every new animation and count-up into the final value at once; nothing animated may be the only way to learn a number (the number is always in the DOM text, the count-up only animates the visible text, the accessible value is the FINAL value).
- Screen readers: a counting number must not be announced on every tick: the animated text is `aria-hidden` and a visually hidden span holds the final value (or the live region updates once).
- Haptics: only where `navigator.vibrate` exists; short patterns; an opt-out the pilot can find (account menu); never during the prologue opening if it would be intrusive (decide: allowed, same opt-out).
- 390px phone: no horizontal overflow from new elements.
- Tests: run only the specs of touched files; no browser, no e2e (grep `apps/web/e2e` for changed literals: the wallet text, the result popup credits, the help paragraphs).
- `apps/web` must not import API code. No server change.

## Review Focus

- A number that changes while it is still counting (two rewards in a row): the count continues from the CURRENT displayed value to the new final value, never jumps back, and ends exactly on the final value.
- A number that decreases (a purchase): counts down with the loss style; zero and negative values format correctly (`−` sign, thousands separators in the active locale).
- Initial render: no count-up on first mount (a page load must not animate from 0); only changes after mount animate (the wallet on load shows the value at once).
- Reduced motion: values appear instantly, no CSS animation runs, haptics still work (they are not motion) but follow their own opt-out.
- The opt-out persists (localStorage in try/catch), defaults ON, and the toggle is reachable on phone and desktop; `navigator.vibrate` missing or throwing is harmless.
- The reward moment never blocks: it can be skipped with a tap/Escape and never delays the Close/Continue button; it still works when the popup opens with a stale or zero reward.
- The copy diet: a removed paragraph must remain available (Tip content identical), reachable by keyboard and touch (a tap toggles), and its text still present in the DOM for a11y; the opening's dialogue steps may point at those paragraphs (`data-tour`/selectors): do not break prologue specs.
- No orphaned i18n keys; the same help text must not be duplicated in two keys.

### Task 1: one count-up for every number that changes

**Files:** create `ui/use-count-up.ts`, `ui/use-count-up.spec.ts`, `ui/CountUp.tsx`, `ui/CountUp.spec.tsx`; modify `ui/kit/ResourceChip.tsx` (+ its spec), `ui/AccountMenu.tsx` (+ spec), `features/report/report.page.tsx` (the `debrief-credits` figure), styles.

**Interfaces:**
- `useCountUp(value: number, options?: { durationMs?: number; stepMs?: number }): { shown: number; direction: 'rise' | 'fall' | null }`: returns the displayed number; on the FIRST render it equals `value` with no animation; when `value` changes after mount it counts from the currently displayed number to the new value (default 600 ms, 30 ms steps, ease-out), cancels a running count when a newer value arrives (continuing from the displayed value), ends exactly on `value`; `direction` is set during the change and cleared after a flash time (900 ms, as `ResourceChip` does); with `prefers-reduced-motion: reduce` it returns `value` at once and `direction: null`.
- `<CountUp value format? className? />`: renders the animated text in an `aria-hidden` span plus a visually hidden span with the FINAL formatted value; `format` defaults to `Intl.NumberFormat(i18n.language)`.
- `ResourceChip` is refactored to use `useCountUp` (same behaviour and classes `kit-chip--rise/fall`, its existing spec stays green); the wallet in `AccountMenu` (the `wallet-chip` showing `credits`) uses `CountUp` with the unit `¢`, keeping `walletAnswer` pulse/delta, `data-testid="topbar-wallet"` and its `aria-label`; the report debrief credits figure counts up when the report opens.
